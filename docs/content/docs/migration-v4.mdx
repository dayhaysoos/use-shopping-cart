Guide for upgrading from v3.x to v4.0.

## Overview

Version 4.0 brings significant improvements while staying API-compatible with v3.x checkout-session mode. The main changes include:

- **Redux Removal**: Now uses React's native `useSyncExternalStore`
- **Modern Stripe Features**: Phone collection, promotion codes, automatic tax, etc.
- **React 19 Support**: Full compatibility with React 19
- **Client-Only Deprecation**: Client-only mode is deprecated (still works, but not recommended)
- **Improved TypeScript**: Better type inference and exported types
- **Smaller Bundle**: Reduced bundle size without Redux

## Breaking Changes

### Client-Only Mode Removed

**Breaking:** `cartMode="client-only"` is no longer supported. You must use checkout-session mode with a server endpoint.

### Node.js 22+ Required

The package now declares `"engines": { "node": ">=22" }`. This applies to the Node.js version that runs your build and your server (where you call `validateCartItems`).

### Build File Paths Changed

Imports through `use-shopping-cart`, `use-shopping-cart/core` and `use-shopping-cart/utilities` are unchanged. Importing `use-shopping-cart/dist/...` was already blocked by the package's `exports` map. Only tooling that bypasses it and points at a file breaks: an absolute path, a Jest `moduleNameMapper`, a bundler alias, or a CDN URL.

| v3                        | v4                                          |
| ------------------------- | ------------------------------------------- |
| `dist/react.es.js`        | `dist/react.mjs`                            |
| `dist/react.js`           | `dist/react.cjs`                            |
| `dist/core.es.js`         | `dist/core.mjs`                             |
| `dist/core.js`            | `dist/core.cjs`                             |
| `utilities/serverless.js` | `dist/utilities.mjs` / `dist/utilities.cjs` |

`dist/react.umd.js` and `dist/core.umd.js` keep their names.

### Errors Are `CartError`s

Errors thrown by the cart, `useCartActions` forms, `validateCartItems` and `redirectToCheckout` are now `CartError`s with a `code` (for example `ITEM_NOT_IN_CART`, `NOT_IN_INVENTORY`). Messages are unchanged. Validation errors previously had `name: 'ValidationError'`; they now have `name: 'CartError'`. `useCartActions` states have a new `errorCode` field. See [error codes](/docs/concepts/shopping-cart-class#error-handling).

### `CartConfig` Is Its Own Type

`CartProvider` props and the `ShoppingCart` constructor take only `cartDetails`, `currency`, `language`, `shouldPersist`, `persistKey` and `storage`. Other fields, like `cartCount` or `shouldDisplayCart`, were accepted before and silently ignored or copied into state; they're now type errors. `shouldPersist` is no longer part of the cart state (`useShoppingCart().shouldPersist` and `initialState.shouldPersist` are gone).

### `validateCartItems` Matches More ID Fields

Inventory is now matched by `id`, `price_id`, `sku_id` and `sku` (first match in `inventory` wins), the same fields the cart uses for item IDs. Carts with items added by `price_id` or `sku_id` alone now validate instead of failing with "not in your inventory". Check your inventory if one product's `price_id` or `sku_id` can equal another product's `id` or `sku`: the earlier product now matches.

### `redirectToCheckout` Is a Standalone Function

Import it instead of reading it from the cart, and pass the Checkout Session URL. Session IDs, the `stripe` prop and `changeStripeKey` are gone: Stripe removed `redirectToCheckout({ sessionId })` from Stripe.js, and a session URL needs no publishable key.

```jsx
// Before
const { redirectToCheckout } = useShoppingCart()
await redirectToCheckout(sessionId)

// After: return session.url from your server
import { redirectToCheckout } from 'use-shopping-cart'
redirectToCheckout(sessionUrl)
```

### `useShoppingCart(selector)` Is Back

As in v3, `useShoppingCart` takes an optional selector, and the component re-renders only when the selected value changes:

```js
const cartCount = useShoppingCart((cart) => cart.cartCount)
```

Cart methods (`addItem`, `incrementItem`, `removeItem`, ...) and cart state (`cartCount`, `cartDetails`, ...) are unchanged.

## What's Changed

### 1. Redux Removal (Internal Change)

**Impact:** None on your code

**What happened:**

- Removed Redux as an internal dependency
- Now uses React's native `useSyncExternalStore` hook
- Uses a custom `ShoppingCart` class with pub/sub pattern

**Benefits:**

- **Smaller bundle size**: ~40% smaller
- **Better performance**: Fewer re-renders
- **Simpler mental model**: No Redux concepts to understand
- **React 19 compatible**: Works with React's latest features

**Migration:** No action required. This is an internal refactor.

### 2. Client-Only Mode Removed

**Impact:** Projects using `cartMode="client-only"` must migrate

**Status:** Removed in v4.0

**Required:** Migrate to checkout-session mode

#### Migration Example

**Before (Client-Only - v3.x):**

```jsx
import { CartProvider } from 'use-shopping-cart'
;<CartProvider
  mode="payment"
  cartMode="client-only"
  stripe={STRIPE_KEY}
  successUrl="https://yoursite.com/success"
  cancelUrl="https://yoursite.com/cancel"
  currency="USD"
>
  <App />
</CartProvider>
```

**After (Checkout-Session - v4.0):**

```jsx
import { CartProvider } from 'use-shopping-cart'
;<CartProvider currency="USD">
  <App />
</CartProvider>
```

**Additional Steps Required:**

1. Create a server endpoint to generate checkout sessions
2. Move `successUrl` and `cancelUrl` to server-side
3. Update product data structure (use `id` instead of `price_id`)

**See:** [Getting Started](/docs/getting-started) for detailed setup guide.

### 3. React Version Requirement

**Before:** React 16.8+

**After:** React 19+

**Migration:**

```bash
npm install react@19 react-dom@19
```

## Checkout Features

For checkout-session mode, modern Stripe features (phone collection, promotion codes, automatic tax, custom fields, shipping options, etc.) should be configured **server-side** when creating your checkout session:

```js
// In your server endpoint
const session = await stripe.checkout.sessions.create({
  mode: 'payment',
  line_items,
  success_url: `${origin}/success`,
  cancel_url: origin,

  // Configure Stripe features server-side
  phone_number_collection: { enabled: true },
  allow_promotion_codes: true,
  automatic_tax: { enabled: true },
  shipping_options: [
    {
      shipping_rate_data: {
        display_name: 'Standard Shipping',
        type: 'fixed_amount',
        fixed_amount: { amount: 500, currency: 'usd' }
      }
    }
  ]
})
```

**See:** [Stripe Checkout Session API](https://stripe.com/docs/api/checkout/sessions/create) for all available options.

## Performance Improvements

### Reduced Bundle Size

- **Before (v3.x):** ~45 KB (minified + gzipped)
- **After (v4.0):** ~27 KB (minified + gzipped)
- **Savings:** ~40% smaller

### Fewer Re-renders

Thanks to React's `useSyncExternalStore`, components only re-render when the specific cart data they use changes.

## API Stability

### Unchanged APIs

All existing APIs continue to work:

✅ `addItem(product, options?)`
✅ `incrementItem(id, options?)`
✅ `decrementItem(id, options?)`
✅ `setItemQuantity(id, quantity)`
✅ `removeItem(id)`
✅ `clearCart()`
✅ All cart properties (cartCount, totalPrice, etc.)

### Deprecated (Still Works)

⚠️ `cartMode="client-only"` - Use `checkout-session` instead
⚠️ `checkoutSingleItem()` - Only works with client-only mode

## Step-by-Step Migration

### Step 1: Update Dependencies

```bash
npm install use-shopping-cart@rc react@19 react-dom@19
```

### Step 2: Test Your Application

Run your application. Everything should work as before.

### Step 3: Configure Stripe Features (Server-Side)

If you want modern Stripe checkout features, configure them in your server endpoint:

```js
// pages/api/create-checkout-session.js
const session = await stripe.checkout.sessions.create({
  mode: 'payment',
  line_items,
  success_url: `${origin}/success`,
  cancel_url: origin,

  // Configure features server-side
  phone_number_collection: { enabled: true },
  allow_promotion_codes: true,
  automatic_tax: { enabled: true }
})
```

### Step 4: Migrate from Client-Only (If Applicable)

If using `cartMode="client-only"`, plan migration to `checkout-session`:

1. Create server endpoint for session creation
2. Update CartProvider configuration
3. Test checkout flow
4. Deploy

**See:** [Getting Started](/docs/getting-started) for complete setup guide

## Troubleshooting

### React Version Errors

**Error:** "Invalid hook call" or "React version mismatch"

**Solution:** Ensure React 19 is installed:

```bash
npm install react@19 react-dom@19
```

### TypeScript Errors

**Error:** Type errors after upgrading

**Solution:** Update @types packages:

```bash
npm install -D @types/react@19 @types/react-dom@19
```

### Checkout Not Working

**Issue:** Checkout redirects not working

**Check:**

1. Your server endpoint returns `session.url` (not `session.id`)
2. You pass that URL to `redirectToCheckout`

## Summary

### Mostly Compatible ✅

- Cart methods and cart state work as before
- Check the [breaking changes](#breaking-changes): `redirectToCheckout` is now an import that takes `session.url`, `CartConfig` is narrower, and errors are `CartError`s
- Opt in to new features when ready

### Major Improvements ✨

- 40% smaller bundle size
- Better performance
- React 19 support
- Improved TypeScript
- Simpler architecture

### Removed ❌

- Client-only mode (must migrate to checkout-session)
- All client-only mode props (`mode`, `cartMode`, `successUrl`, `cancelUrl`, `billingAddressCollection`, `allowedCountries`)
- Support for Node.js versions below 22
- The old `dist/*.es.js` / `dist/*.js` file names (use the package entry points)

**If you're using checkout-session mode in v3.x, upgrading to v4.0 is seamless. If you're using client-only mode, migration is required but straightforward.**
